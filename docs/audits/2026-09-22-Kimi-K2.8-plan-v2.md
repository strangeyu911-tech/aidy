## 3. 分阶段修复计划（v2，RC1 步骤内容随 §6 裁决定稿）

### 第 1 步｜RC3 富化幂等 + 重试剥离（P0，先做）
- **落点**：`daily-supervisor.js`（`appendInternalContext`）、`app.js`（`scheduleSystemMessageRetry`）。
- **做法**：`appendInternalContext` 幂等化——追加前先剥离已存在的内部块（已知前缀+边界精确匹配），再追加当前块。单点覆盖两条重入队路径，顺带清历史队列残留。**剥离实现唯一**（K7），供第 4/7 步 `[PLAN_COMMIT]` 标记剥离与内部指令分离共用；**出站文本与写入会话转录的文本都过同一剥离函数**。
- **验证**：A3（连续富化 3 次块计数恒 1；路径 B 重试序列文本不增长；补路径 B 单测）。

### 第 2 步｜RC2 random 过期即弃 + 用户回合优先（P0）
- **落点**：`supervision-policy.js resolveDueCheckpointAction`（age 判定下沉，K9）、`app.js flushPendingSystemMessages`（message 层兜底）、`app.js:393-398 / :1050-1056`（A2b）。
- **做法**：① random 消息 dueAt 超 **10 分钟**未发即弃，沿用 `expired` 事件形态；checkpoint 层作唯一真源，避免「消息丢弃但 checkpoint 记 completed」的状态失真。② 同批 pending 时用户回合优先，主动消息退避。**优先级显式定义：random 走 age、非 random 走 attempt（K2）**。
- **A2b 落地条件（V1/V2）**：a) `flushPendingInboundMessages` 与 `flushPendingSystemMessages` 当前在 `Promise.all` 并发（`app.js:393-398`），且入站侧派发前已 pop draft（`:1231`）→ **必须改为串行**（先入站 flush、后系统 flush），否则"有用户消息待发"的判据读到空、退避随机失效；b) 与既有 `skipCheckin: messages.length > 0`（`:396`）**合并为一套优先级判断**，不并存两套；c) 定位写清：A2b 只缩小"主动消息还在队列里"的乱序窗口，**在飞 turn 无法让位**（事故分支由 age 丢弃 + RC3 兜底）。
- **验证**：A2 + A2b。

### 第 3 步｜RC1 缓解：跨 scope 当日摘要注入（A2 方案，v2.1 定稿）
- **落点**：`app.js enrichIncomingMessageWithZhijiantimeFreshRead`（704-727）。
- **做法**：给用户回合 prompt 追加「本轮之前的主动触达记录」摘要——**来源必须是模型最终送达文本（或剥离 `[Zhijiantime…]` / `[CyberBoss supervision note]` 等已知内部块后的文本），禁止直接用队列消息原文**（重试过的消息自带内部块，D5）；限条数（当天）、限字数，显式声明"这是助手侧已发出的主动消息"。
- **定位**：这是**缓解非根治**——消除"重新打招呼"症状，不动会话架构；路线 A/B 见 §6 处置。
- **验证**：A1（含"注入文本不含任何内部块前缀"断言）。
- **出队后**：若未来路线 A 立项落地，本步可退役（注入块关闭后 A1 仍须成立）。
- **路线 A 立项时的两条配套设计（v2.1 补，回应"永久污染"担忧）**：
  1. **触发文本日志体**：系统回合 trigger 从命令体（"SYSTEM ACTION MODE…"）改为简短日志体（如「[20:00 系统查岗] 指尖时光仍空，已催办」），降低模型被带偏与每轮回读成本；
  2. **定期会话轮换**：ACP 有 `session/new` 通道，艾迪可每 1–2 周主动开新会话、首条 prompt 放"搬家摘要"（近期聊天要点与未完成约定），旧会话弃用——把"转录永久污染"变为"周期性清零"。
  - 🔴 **2026-09-22 实施前纠正**：本条原文称「不依赖 runtime 新增能力」，**低估了前置条件**。写「搬家摘要」要求 Aidy **自己**知道近期聊了什么，而历史在 runtime 侧（`2026-09-22-kimi-plan-v1-review.md` 第 3 条），故**必须先新增「入站用户消息本地留存」**。这属于**隐私决策**（把用户对话落到本地），**须用户明确同意**方可实施；与是否走路线 A 无关，是独立门槛。技术通道本身（`session/new`）确实存在。
  - 🔴🔴 **2026-09-22 14:20 用户裁决：本条整体取消，不再实施。** 用户的产品形态要求是「**模型侧记忆永不清零**，这样它才能越来越懂用户」—— 周期性换会话正是它的反面。**前提本身错了**：本条把「共享转录里累积日志体行」当作必须清除的污染，而用户不认为那是污染。连带取消「入站消息本地留存」→ 新增隐私面不存在。
  - ✅ **同时更正一条事实**：不必为「搬家摘要」新建留存 —— 转录**就在本机明文**（`~/.codebuddy/projects/d-codebuddy-dist-win-unpacked-resources/*.jsonl`，实测 78,553 B / 43,242 B 两份）。将来若确需摘要，直接读它即可。**本条真正需要跟进的问题已变为「上下文窗口上限」**（共享会话增长到某点会被迫压缩或失败，codebuddy 压缩策略未查证），**不是隐私**。
- **用户可见性结论（已核实）**：机器指令对**用户完全不可见**——微信侧 `stream-delivery.js` 只投递自然语言（路线 A 不改变此行为）；桌面 renderer 无会话转录展示界面。污染仅存在于模型侧记忆。

### 第 4 步｜RC6 承诺捕获：模型判断 + 裸时间确定性兜底（K5/K6/K7 修正版）
- **落点**：`daily-supervisor.js capturePlanningCommitment`（92-134，硬编码话术在 `:132`）、`app.js:737-746`、`explicit-checkpoint.js`。
- **做法**：
  1. **主路径 = 模型判断**：awaiting 态注入指令，用户给出做计划时间时模型输出 `[PLAN_COMMIT iso-time]` 标记 → 解析标记 → 时间值经确定性解析器校验 → 建 checkpoint → 发送前用**第 1 步的统一剥离实现**剥掉标记。
  2. **确定性兜底 = 裸时间直通**：新增 `isBareTimeExpression(text)` 取值口（K6）——「21:00」不经模型直接建承诺，100% 可靠。
  3. **话术诚实化**：`:132` announcement 从硬编码改为复述解析结果；误解析裸露。
